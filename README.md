# 도쿄 산보 — 4박5일 여행 앱

2026.08.16–20 도쿄 여행용 홈 화면 앱(PWA). 고탄다 베이스, 1인, 35mm 촬영 중심.

👉 https://spring7day.github.io/tokyo-sanpo/

## 아이폰에 추가하기

사파리로 위 링크를 열고 → 공유 버튼(□↑) → **홈 화면에 추가**.
한 번 온라인에서 실행하면 이후 비행기 모드에서도 일정·설명·주문 문장이 그대로 뜬다.

## 화면

| 탭 | 하는 일 |
|---|---|
| **지금** | 현재 시각 기준으로 지금 할 것 / 다음 일정 / 남은 시간. 11–16시엔 폭염 경보 |
| **일정** | D1–D5 타임라인. 접힌 상태는 한 줄, 펼치면 사진·설명·이동법·주문 |
| **동네** | 산보노트가 다룬 동네 24곳. 태그 필터. 일정을 벗어나 즉흥으로 움직일 때 |
| **지도** | 그날의 번호 핀 + 동선 폴리라인. 날짜별 전환, 동네 전체 보기 |
| **정보** | 교통 · 폭염 · 혼자 걷는 사람에게 · 촬영 · 결제 |

각 장소에는 **✦ 클로드에 물어보기** 버튼이 있다. 장소명·일본어 상호·주소·주문 메뉴와
"혼자 여행, 일본어 못 함" 같은 조건을 미리 채운 새 대화를 연다.
누르는 순간 같은 내용이 클립보드에도 복사되므로, 앱이 프리필을 못 받아도 붙여넣기로 이어진다.

## 콘텐츠 근거

장소 선정은 유튜브 채널 [산보노트](https://youtube.com/playlist?list=PLGbyawO8vH2pLoAxS97T04Gi_4UAY4Szg)의
도쿄 재생목록 **29개 영상**을 근거로 했다. 영상 썸네일이 붙은 항목은 채널이 직접 다룬 곳이고,
탭하면 **해당 챕터 시각부터** 재생된다 (챕터 232개, 설명란 명시 장소 66곳에서 추출).

데이터의 `src` 필드가 근거 등급을 나타내고, 앱에서도 각 항목에 배지로 표시된다.

- `video` — 산보노트 영상이 직접 다룬 장소
- `checked` — 타베로그·공식·일본 매체로 교차검증된 식당. **평점은 이 등급에만 적는다**
- `naver` — 한국어 방문기 다수로 실재·혼밥 가능까지 교차확인. 평점은 적지 않는다
- `pick` — 동선상 후보. 현장 확인이 전제

`solo` 필드는 혼밥 난이도를 **"말을 얼마나 해야 하는가"** 로 표시한다
(🔇 식권 자판기 / 👉 메뉴 짚기 / 🍽 카운터석 / 🤫 대화 금지 공간).
혼자 다니는 여행자에게는 평점보다 이쪽이 실전에서 쓸모 있다.

## 이 일정의 성격

조용한 1인 여행자 기준으로 짰다. 사흘에 걸쳐 100년 된 킷사텐을 하나씩 넣었고
(명곡킷사 라이온 1926 · 카야바 커피 1938 · 카페 파울리스타 1911),
셋 다 그날 가장 더운 시간대에 배치해 폭염 대피처를 겸하게 했다.
식당은 카운터석과 식권 자판기 위주로 골랐다.

## 알려진 한계

- **타베로그를 제작 환경에서 열 수 없었다.** 그래서 평점을 지어내는 대신 근거 등급을 나눴다.
  `checked` 외에는 평점을 적지 않는다. 개인 가게의 정기휴일은 바뀌기 쉬우니
  방문 전 구글맵 영업 상태 확인이 필요하다.
- 교차검증에서 걸러낸 것들: 카야시마(기치조지)는 정기휴일이 '제3 수요일'과 '수요일'로
  자료가 갈리는데 8/19가 8월의 제3 수요일이라 1순위에서 내렸고,
  사쿠라자카(시부야)는 한국어 방문기가 0건이라 월요일 영업을 확인하지 못해 대안을 붙였다.
- 지도 핀은 위치 감각용 근사 좌표다. 실제 길찾기는 각 항목의 구글맵 버튼(정확한 일본어 상호+주소 검색)을 쓴다.
- 영상 음성·자막은 API가 막혀 읽지 못했다. 근거는 제목·설명·챕터까지다.

## 구조

```
.
├── index.html          앱 (UI + 로직)
├── data.js             일정·동네·정보 데이터
├── sw.js               서비스 워커 (오프라인)
├── manifest.webmanifest
├── make_icons.py       도리이 아이콘 생성기 (zlib만 사용)
└── icons/
```

일정을 고치려면 `data.js`만 건드리면 된다. **단, 고친 뒤에는 반드시 버전을 함께 올린다.**

```
index.html  <script src="data.js?v=N">
sw.js       const DATA_V = "N";      ← 위와 같은 값
sw.js       const VERSION = "vN";    ← 정적 자산(아이콘·CSS·JS)까지 바꿨을 때
```

서비스 워커가 `data.js`를 캐시하기 때문에, URL의 `?v=`를 올리지 않으면
이미 앱을 설치한 기기는 **옛 일정을 계속 본다**. `?v=`가 바뀌면 캐시에 없는 URL이 되어
구버전 서비스 워커에서도 즉시 새 내용을 받는다.

`data.js`는 네트워크 우선 + 캐시 폴백으로 처리하므로 온라인이면 항상 최신이고,
새 서비스 워커가 붙으면 앱이 스스로 한 번 새로고침한다.
